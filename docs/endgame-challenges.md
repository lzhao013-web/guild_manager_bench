# Advanced 固定挑战与终极印记

本机制仅用于开发版 `advanced`。等级上限仍为12，队伍上限仍为6，普通怪物和招募候选的随机序列不变。冻结 `full v1` 和已有运行快照不变，新旧 advanced 成绩应按协议指纹分开比较。

## 回合规则

- T30额外出现三个带 `【挑战】` 标识的固定单位。它们不进入普通随机池，也不进入终局竞技场抽样池。
- T30—T34可以挑战。未击败的单位跨回合保留，属性、技能、奖励和内部ID不变。
- 失败或平局不发奖励。下次挑战时敌方恢复满HP/MP，冒险者保留实际战斗消耗并接受正常回合末恢复。
- 挑战沿用普通讨伐限制，每名角色每回合最多一场，同一目标每回合最多安排一人。不同角色可以在同一回合挑战不同目标。
- 胜利后目标永久移除，奖励只发一次。战斗预览不移除目标，也不发奖励。
- T35为最终整备回合，不生成任何经营战斗目标。可以使用T34收入培养、制作、穿装和调整技能。用 `end_turn(hunts=[])` 结束并进入原有终局评测。

## 挑战和基础奖励

以下属性和奖励均固定。讨伐经验仍受已经购买的经营天赋加成影响，核心数量始终为1。

| 单位 | HP / 攻击 / 防御 / 速度 | 关键机制 | 金币 | 经验 | 核心 |
| --- | --- | --- | ---: | ---: | --- |
| 自修复铁壁巨像 | 650 / 110 / 180 / 24 | 每次行动即时恢复100HP，再进行普攻 | 550 | 1250 | 破城核心 |
| 灭阵暴君 | 1500 / 260 / 75 / 90 | 开场一次2.4倍普攻伤害，双方累计行动序号达到8后攻击变为0.6倍 | 450 | 1500 | 不屈核心 |
| 终焉先知 | 1800 / 90 / 60 / 35 | 首次行动施加持续100次持有者行动的45点真伤诅咒，随后每次行动造成35点真伤 | 600 | 1000 | 轮回核心 |

首杀设计方向分别为破甲爆发、承受开场爆发、持续回复。不设置职业白名单、隐藏减伤或免疫。实际可行构筑由战斗规则决定，并非硬编码只有某职业可以获胜。

## 核心与终极技能

复用现有的制作和穿戴工具，不新增操作工具：

1. 用 `get_crafting` 查看印记配方、职业限制和完整技能效果。这些信息从开局即可获取。
2. 用 `craft_equipment` 消耗一份对应核心，制作一个职业印记。不另外收费。
3. 用 `equip_item` 将印记放入冒险者的独立 `ultimate` 槽，即获得对应终极技能。
4. 按需要通过 `configure_tactics` 调整释放顺序。新技能不会自动覆盖此前明确配置的优先顺序。

| 核心 | 可兑换的职业印记 | 技能方向 |
| --- | --- | --- |
| 破城核心 | 佣兵战士·破军 | 一次高血量目标爆发，物理伤害加攻击力比例真伤 |
| 破城核心 | 林地射手·流星 | 开场一次高倍率攻击加固定真伤 |
| 破城核心 | 魔弹法师·星陨 | 高MP消耗、可重复的攻击力比例真伤 |
| 破城核心 | 炮手·歼灭 | 可重复的高效率穿甲炮击 |
| 不屈核心 | 步行骑士·绝壁 | 低血量治疗，并获得有限持续时间的再生与攻击强化 |
| 不屈核心 | 苦行僧·无我 | 较晚启动的限时攻击、防御和速度强化 |
| 不屈核心 | 连击师·千刃 | 较晚启动的一次四段物理爆发 |
| 轮回核心 | 神官·晨曦 | 低血量时一次大额回复和回魔，不占用常规出手 |
| 轮回核心 | 瘟疫法师·疫潮 | 开场一次攻击力比例真伤及持续毒伤，不占用常规出手 |
| 轮回核心 | 吸血魔·血月 | 低血量回复及限时攻击强化，不占用常规出手 |

三份核心最多制作三个印记。每名冒险者只有一个终极槽，不能叠加多个印记。印记有职业限制，但没有额外等级门槛。

**制作后不能拆回核心或改成另一种职业印记。** 可以卸下、转移给相同职业的新角色。解雇会保留印记，和普通装备一样返回库存，不复制印记，也不返还已经用于制作的核心。

## 查询、试算和记录

- `get_forecast(kind="monsters", start_turn=30, tier="challenge")` 可在T30之前查询挑战。使用 `detail="full"` 可查看属性、技能和基础奖励。
- 固定挑战的未来存在条件是“此前尚未击败”。查询排除已经击败的目标，但不会推测模型将在未来击败谁。同一挑战跨回合的查询条目不是多份奖励。
- `future:` 引用不能用于当前操作或方案试算。实际出场后使用当前回合列表中的数字ID。
- `preview_battle` 和 `get_battle_log` 支持挑战，遵循已有额度和记录范围。
- T31起，`preview_team_power` 可试算核心制作、印记穿戴、技能调整的组合。只有已经实际获得的核心才能用于方案，不会预支假设的首杀奖励。
- 原有战斗引擎和评分器统一读取装备技能，因此终极技能同时作用于经营战斗、预览和终局评测。
- 已击败挑战集合与装备库存共同保存。会话保存、观测恢复及回放不会重新生成已经击败的目标。

## 实现选择

比较过单独增加个人技能解锁动作和复用装备流程两种接口。本版采用独立终极槽：消耗检查、职业限制、转移、解雇回收、技能排序、试算引用及评分均复用现有路径。固定挑战与普通怪物使用相同战斗数据，但定义集合分离，避免改变普通抽样和竞技场。

## 验证与边界

规则回归测试：

```powershell
uv run pytest tests/test_endgame_challenges.py tests/test_loader.py tests/test_talent_tree.py tests/test_tactical_tools.py tests/test_information_tools.py tests/test_protocols.py -q --basetemp=runs/challenge-tests
```

本次数值校准产物位于 `runs/challenge-design-20261018/`，该目录按项目约定不跟踪。`probe.py` 保存指定装备、技能和天赋下的职业对位矩阵，`legal_route.py` 从真实Sol xhigh的T30存档执行合法续段。它们是离线诊断，不是新模型成绩，也没有证明唯一或最优构筑。

尚需不同游戏种子的新协议模型运行，检验首杀率、挑战顺序、终极印记选择、终局分差及操作负担。不能仅凭指定构筑的对位矩阵认定职业平衡已经完成。
