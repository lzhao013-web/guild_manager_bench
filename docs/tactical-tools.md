# 方案试算、执行与技能配置

本页说明开发版 `default`、`advanced` 的 LLM 工具。方案试算和凭据执行在所有游戏回合可用，正式战力估算仅在 preset 配置的终局阶段开放。未配置终局起始回合时，只提供方案预检，不计算战力。冻结的 `full v1` 保持原协议。

## 方案试算

`preview_team_power(operations)` 按顺序预检最多20步准备动作，不改变真实状态，不消耗游戏资源，也不写入会话事件。每次试算扣1次调用预算，非法方案的试算也扣1次。

支持当前启用的制作、招募、解雇、经验分配、天赋购买、穿脱装备、技能配置和付费刷新。不能嵌套查询、预览、执行方案、备忘录或结束回合。

```json
{
  "operations": [
    {"tool": "recruit_adventurer", "arguments": {"candidate_id": 1}, "as": "hero"},
    {"tool": "craft_equipment", "arguments": {"recipe_id": 1}, "as": "weapon"},
    {"tool": "equip_item", "arguments": {"adventurer_id": "$hero", "equipment_instance_id": "$weapon"}}
  ]
}
```

真实对象使用本回合数字编号。招募与制作步骤可用 `as` 定义局部名称，后续步骤通过 `$名称` 引用。名称不能重复，角色与装备引用不能混用。这些名称只在本方案内有效，试算产生的内部编号不能用于真实操作。

合法非空方案返回：

- `changes`：预计的资源、属性和装备变化，不是已经发生的变化。
- `operation_count`、`required_calls`：方案步数，以及提交时必须满足的最低预算余额。
- `remaining_calls`：本次试算扣费后的剩余预算。
- `can_execute`：按试算后的余额判断，现在是否满足提交门槛。
- `plan_id`：绑定当前游戏状态与固定方案内容的执行凭据。

终局前不计算或返回综合战力、预测胜率或评分差值。终局阶段额外返回 `current_rank_score`、`projected_rank_score` 和 `rank_score_delta`，均使用正式 `rank_score`。差值相对于调用前的真实状态，不是相对于回合开始。

`operations=[]` 可预检当前状态，在终局阶段查询当前正式评分。空方案不签发执行凭据。方案非法时返回具体失败步骤，不返回部分方案或评分。

## 凭据执行

```json
{"plan_id": "试算返回的凭据"}
```

调用 `execute_plan` 提交方案。成功与失败均不扣调用预算，但提交时的剩余预算必须不少于方案步数。余额由运行器提供，模型不能指定。

例如剩7次时试算6步方案，试算后剩6次，可以提交。提交后仍剩6次。如果先查询一次，只剩5次，就不能再提交这套6步方案。余额不足时整单拒绝，明确返回所需与剩余次数，不改变真实状态，不扣费。应缩短方案后重新试算或结束回合，不要原样重试。

凭据规则：

- 只读查询、战斗预览和其他方案试算不会改变游戏状态，因此不使凭据失效，但收费调用会减少余额。
- 成功执行其他准备动作后，旧凭据失效。即使操作来自同一会话的其他调用入口，也必须重新试算。
- 失败且未改变状态的真实动作不使凭据失效，但通常会消耗调用预算。
- 凭据仅限原会话和原回合，不能跨会话或跨回合使用。
- 同一凭据只成功执行一次。同回合重复提交返回已有结果，并标记 `already_executed=true`，不重复扣资源或追加事件。

执行在整批校验成功后一次性提交状态，并为每个真实动作记录正常准备事件。不会因为后续步骤失败而留下部分方案。结果中的逐步事件用于回放、续跑和动作统计，恢复时只重放已提交动作，不重新计算试算或战力。

这套规则限制的是收费调用与单批提交资格，不再限制累计真实动作数量。免费执行与旧规则不能视作同一评测协议。开发存档的协议指纹会随实现变化，历史结果不回写，冻结 `full v1` 不变。免费拒绝仍受每回合模型请求步数上限约束。

## 技能配置

preset 启用 `expose_tactics` 时，可调用 `configure_tactics`：

```json
{"adventurer_id": 1, "skill_priority": ["skill_id"], "disabled_skills": []}
```

`skill_priority` 按优先级从高到低排列普通主动技能。未列出的普通主动技能仍按默认顺序检查。`disabled_skills` 停用指定主动技能。自动回复技能只能停用，不能排序。被动技能不受影响。

两项均传空列表恢复默认。配置持续生效于经营战斗、战斗预览和终局评测，不改变技能自身的触发条件、法力消耗或次数限制。该动作也可放入方案。
