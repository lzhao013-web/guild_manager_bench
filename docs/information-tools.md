# 战斗记录与未来刷新查询

这些工具在开发版 `advanced` 中开放。冻结 `full v1` 不变，查询各消耗一次普通工具调用，不占战斗预览次数。

## 按编号查询战斗记录

`preview_battle`、`end_turn` 的战斗结果会直接返回 `battle_id`。上回合实战编号也会出现在下回合初的战报中，恢复存档后保持一致。直接复制编号查询，无需选择来源或先查目录。

```json
{"battle_id": "preview:T1:1"}
```

默认返回双方普攻、技能、伤害和治疗统计。查看逐行动事件时指定 `detail=events`，每页固定20条。

```json
{"battle_id": "preview:T1:1", "detail": "events"}
```

若返回非空的 `next_cursor`，保持编号和视图不变，将该值作为下一次的 `cursor`。

```json
{"battle_id": "preview:T1:1", "detail": "events", "cursor": 20}
```

- 只可查询当轮已执行的预览与上一回合的实战。过期或不存在的编号返回失败，不会重新模拟。
- 编号只用于日志，不是角色或怪物的可操作编号，也不能跨会话读取记录。
- 记录保留当时状态，不随换装、解雇或刷新怪物而改变。预览缓存不写入存档。
- `left` 表示冒险者，`right` 表示怪物。即时技能附带的普攻合并在技能事件中。
- 伤害可能包含溢出值，日志不记录逐行动MP余额或技能跳过原因。

## 未来刷新查询

`get_forecast` 的接口和功能保持不变。它查询未来经营回合的自然怪物或招募候选，不改变真实状态，不包含终局评测敌人。

```json
{"kind": "monsters", "start_turn": 5, "end_turn": 10, "material": "bone", "limit": 10}
```

可按名称、怪物类型和材料筛选。默认返回简表，`detail=full` 展开完整属性与技能。简表每页最多10条，完整详情每页最多3条，通过 `offset/limit` 翻页。单回合还可用 `entry_index` 定位条目。

`future:` 引用不能用于当前操作。怪物奖励是未计经营天赋加成的基础奖励，固定挑战仅在此前未击败时存在。手动刷新不会改变后续自然刷新序列。

## 协议范围

按编号查询和分离刷新工具属于新的开发协议快照。旧开发版存档需使用其原始协议续跑，不兼容旧版 `source/battle_index` 查询参数或 `refresh_monsters` 的 `preview` 参数。
