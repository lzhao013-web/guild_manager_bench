# 运行工作台

工作台在本机 FastAPI 服务中管理任务。浏览器只提交操作和读取状态，不持有 runner 的生命周期。游戏引擎、LLM 适配器和冻结的 `full v1` 文件保持不变。

## 启动

需要 Python 3.11+、uv 和 Node.js 22.20+。从仓库根目录执行：

```powershell
uv sync --all-groups
npm ci
npm run build
uv run guild-manager serve --preset full
```

打开 <http://127.0.0.1:8000/>。前端源码更新后重新运行 `npm run build`。第一次构建必须在服务启动前完成，没有构建产物时首页会提示构建步骤。

人工操作位于 `/legacy/?mode=manual`，原来的 `/?mode=manual` 和 `/?watch=1` 仍有效。旧 LLM 调试页位于 `/legacy/`，它仍使用原来的连接式调试接口，不具备新工作台的任务管理语义。原来的 `/replay/`、对照复盘、经营画像和 `/leaderboard/` 保留。

## 创建与管理实验

可先在左侧“API 配置”保存常用连接，再在每个模型行直接选择。支持从命令历史导入，以及查询服务端模型目录。密钥保存在系统凭证库，配置列表不返回密钥，编辑窗口可直接查看和修改 Key。详见 [API 配置与模型目录](api-profiles.md)。

1. 选择“新建实验”，填写批次名称和 preset。
2. 添加一个或多个模型，选择 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 或 Google Gemini 原生 API。模型、服务地址和 API Key 留空时使用服务端环境配置。
3. 可填写多种推理强度、多个游戏种子和重复次数。工作台展示展开后的任务清单，一个批次最多 64 个 run，待处理任务总数最多 128 个。重复不会自动改变种子。
4. 确认清单后加入队列。在“调度设置”中配置全局并发和每个服务地址的并发，均为 1 到 8，默认均为 2。降低上限不打断已启动任务。服务端点并发不等于 API 请求速率限制。

每个 run 使用独立工作进程。工作台在该进程中将评分执行器限制为单线程，避免多个 run 各自创建整机规模的评分进程池。评分函数、输入和协议指纹不因这项调度设置而改变，CLI 的执行方式也不受影响。

运行中心只展示排队中、启动中、运行中和停止中的 run，按固定顺序排列，状态变化不会自动重排。支持搜索、状态和批次筛选、关注、批量停止、两局对照，以及最多四路观战。已完成、失败和已中断的 run 出现在“历史存档”，未生成存档的启动失败和取消排队也会保留。详情页包含队伍摘要、评分曲线、行动、模型调用、诊断、配置和产物。模型推理只展示 API 实际提供的文本或摘要。

同一存档的首次运行和多次续跑，在界面上始终作为一个 run。状态和统计使用当前执行的数据，不重复累加续跑时恢复的累计用量。批次归属保留首次创建的实验，续跑不新增用户可见的 run 或批次。原执行 ID 的链接、关注和观战选择会定位到同一个 run 的最新执行。内部执行记录和日志仍保留，不删除或改写已有历史。

页面打开期间，run 结束时会出现可关闭的结果通知，失败使用警示提示。列表会移除这个 run，但已经打开的详情或观战面板不会突然关闭。历史页支持查看详情、续跑，以及选择最多四个受控 run 回看。

历史页提供独立的 preset 筛选，可与关键词、批次和状态组合使用。选项来自已记录的受控 run 和 CLI 存档，缺少 preset 的存档可通过“未记录 preset”筛选。直接点击表头的名称、Preset、当前状态、进度、Rank Score 或创建时间排序，再次点击同一字段切换升降序。当前排序列显示方向箭头，并提供键盘操作和屏幕阅读器排序状态，不再单独提供排序下拉框。默认按创建时间从新到旧，数值列首次点击优先降序，名称、Preset 和状态首次点击优先升序。创建时间以本地时区显示，原始时间可通过悬停查看。未知排序值始终排在末尾，零分和第零回合正常参与排序。受控 run 使用当前行的值，不使用旧存档中的过时评分。筛选和排序只影响浏览器列表，不修改存档或改变 run 的归并规则。

任务状态和执行阶段分开展示。页面可见时，浏览器每秒读取一次摘要，连接失败时保留上次成功读取的数据并标注离线。重新连上或刷新后，浏览器从服务端恢复任务列表。运行列表侧栏的原始模型与诊断日志用字节游标增量读取，保留最近 600 个事件。侧栏行动与详细观战按回合读取当前工作任务的完整事件历史，不受该窗口限制。侧栏展示当前回合，其他回合通过专注视图选择。完整记录保留在任务事件文件和原运行归档。

## 详细观战

在总览中选择任务并点击“专注查看”，或多选任务后点击“观战选中”。单局观战默认进入综合总览，同时展示编队、怪物、装备、招募、公会发展、最近行动和模型输出摘要。点击模块标题或摘要中的对象后，模块在同一工作区完整展开，不跳页、不以弹窗查看核心详情。顶部可一键返回总览或直接切换模块，运行状态与回合定位始终保留。多路观战使用专用摘要面板，不再把完整单局详情缩小后放入格子。每路同时显示编队血蓝、怪物、最近有效行动或失败、模型摘要和已记录评分。编队最多显示 6 位，低生命成员提前，怪物最多显示 4 个并提供其余数量入口。点击人物、怪物、行动入口或模型摘要，直接进入该 run 的对应单局模块。返回时保留观看位置。

多路模型区显示一条本次调用信息和最多一行最新正文，等待响应时保留调用信息，不再用模型框撑满剩余高度。空出的区域用于招募候选、天赋与升级、装备与制作、经营进展。预览展示服务端记录的价格、资格和缺口，优先展示满足条件的对象，不按推测的强弱排序。制作摘要先展示满足条件的配方，按当前金币费用从高到低排列，再展示闲装和缺资源配方。配方没有独立阶级字段，不根据名称推断阶级。天赋摘要按可解锁、已记录阶级和金币费用降序排列。闲装仍保留独立计数入口。点击候选、节点、装备或配方可直达完整详情。

预览按实际剩余面积分级：大面板展示对象、费用、效果和条件，小面板保留机会计数、最近操作与重点失败。每类最多展示 8 项，空清单不生成空白卡片，旧快照缺字段会标为未记录。编队已满时收起招募卡，将空间优先用于升级和装备，候选仍可在单局招募模块查看。经营进展只使用当前观看位置之前的行动，展示具体操作、失败和查询数量，不再显示局部曲线。多路曲线通过顶部“对比当前观战曲线”统一查看，不额外请求模型生成摘要。

底部保留回合选择、步骤进度条、上一步、下一步和跟随开关。拖动进度条会冻结到对应历史位置，不停止任务。运行状态、阶段耗时和工具预算描述实时任务，资源、评分与局面摘要来自当前观看位置。多路面板只挂载有界预览，不挂载完整日志、模型输入、装备查看组件或天赋图，完整内容在单局模块中查看。桌面按剩余视口分配网格，三路采用三列，四路采用两行两列。手机采用单列浏览，较矮窗口保留网格并整体滚动，不给每个摘要区域再加滚动条。

- **定位回合**：按回合及重试次数选择记录。失败后回滚的尝试单独保留，并标注“已回滚”。
- **查看行动**：最近行动、完整时间线与多路摘要使用同一套表达。标题保留具体对象和操作，资源消耗、装备归属、属性、天赋和战术变化单独展示。优先使用原事件的中文摘要与变化清单，旧记录缺清单时只比较已保存的前后快照，不推算额外收益。
- **展开时间线**：一次工具调用及其结果合为一条操作。尚未返回时标明执行中，连续查询折叠为一组，运行事件集中收起。失败、重试和回滚提示仍直接显示。没有经营操作时明确提示目前只进行了查询。操作详情列出具体变化与真实讨伐双方及结果，原始事件和参数按需读取。实时跟随时可查看截至当前位置的最近操作详情，不因打开模块而暂停任务。旧记录缺少战果字段时标为结果未记录。
- **点击行动**：队伍、资源和模型调用一起定位到操作的真实结果帧。上一步和下一步仍按原始位置移动，保留调用之前、等待结果、结果之后的观看位置。已回滚尝试中的操作会标明不再生效。
- **暂停跟随**：冻结已经读取的局面与输出，任务继续执行。后续事件不会覆盖当前观看位置。
- **返回实时**：追上最新记录。有新事件时按钮会提示。
- **查看编队**：总览优先显示生命低于上限 30% 的成员，保留角色缩略图、等级和真实生命/法力，最多显示 6 位。展开编队后，通过对象选择框或左右按钮切换成员，在模块内部完整查看属性、装备槽位和技能。点击“收起对象详情”可回到该模块的集合视图。
- **查看装备与技能**：装备按真实槽位围绕角色排列，区分空槽、已穿戴和被其他装备占用。桌面端将选中装备的属性与技能放在槽位图旁边，还可直接定位到同槽库存。攻击、防御和速度优先显示，生命与法力上限保留在状态条中，开启“对比基础”后也会显示这两项的属性差值。装备技能默认显示名称，展开后查看完整效果。
- **查看怪物与招募**：怪物和候选以图鉴卡展示，点击查看详情。怪物以独立的阶级标签和身份标签显示，精英使用星形图标，首领使用皇冠，固定挑战使用旗帜。总览和多路始终展示标签，不依赖名字前缀或悬停。完整属性位于怪物模块和详情，不推测剩余生命或胜率。招募卡只展示当前条件，不执行招募。
- **查看库存**：装备库支持搜索、槽位和穿戴状态筛选。
- **查看制作**：装备模块内可切换到制作配方，按名称和成品槽位筛选。详情显示当前金币费用、原价（快照有记录时）、材料需求与持有量、服务端报告的缺口、成品属性和技能，并可返回同槽库存。所有入口只读，不执行制作。
- **查看天赋路线**：高级天赋横向按真实分支、纵向按已记录层级排列。没有分支标记的旧版升级按前置深度排列，不虚构分支。点选节点后持续突出全部前置路线，实线箭头表示前置，红色虚线表示互斥。节点区分已解锁、可解锁、缺资源、缺前置和互斥锁定，点选详情显示完整金币、经验、材料费用、服务端报告的缺口和关系入口。搜索按名称或 ID 匹配，回车逐个定位，其他分支不会被删除。可拖动空白处平移、缩放、定位选中节点或适应全图。首次缩放保留可读字号，返回模块时保留搜索、缩放和画布位置。
- **查看材料**：顶部保留少量摘要，完整材料以弹出网格展示，避免长文本挤压主画面。所有内容来自所选快照，缺失字段明确显示未记录。
- **查看模型**：总览、多路摘要和完整模型模块都显示本次调用的状态、输入/输出 Token 和耗时。完整模块还显示已报告的缓存 Token、推理 Token、工具调用数，以及模型、接口和配置强度。正文保留在信息条下方，完整输入与原始响应按需读取。推理区仅展示 API 实际返回的文本或摘要。
- **查看战斗**：展示工具返回的战果与奖励。模型已经查询过的战斗日志可以展开查看，不额外执行工具、请求模型或重新模拟。

桌面端压紧运行信息与底部观看控制，将主要空间留给编队、最近行动和怪物。总览卡片不设置内部滚动条。最近行动优先显示具体操作、失败和重试，不用“请求模型”或“运行完成”替代经营内容。连续查询不会刷走这些记录。装备、招募和升级各显示最多 2 项摘要，优先展示未穿戴装备、满足条件的候选和可解锁升级。模型正文显示最多 4 行。展开模块后仍可查看完整记录，小屏幕使用页面纵向浏览。

### 怪物分组与模型调用统计

怪物 T1/T2/T3 依据本机对应 preset 的 `monsters.yaml` 原型分组：首次解锁回合 1—7 为早期 T1，8—17 为中期 T2，18 起为晚期 T3，包含 24、26、28 回合出现的晚期变体。按原型的 `min_turn`，不是当前回合或怪物数值判定，所以后期出现的史莱姆仍是 T1。`challenge` 单独显示为挑战，不冒充普通怪物的首领身份。分组只在界面投影中使用，不改写原始观测或归档。日志没有阶级字段时使用当前本机原型表补充显示，原型未匹配、preset 已移除或原型文件暂不可读时标为阶级未知，不猜测。修改原型文件后，后续读取会更新分组元数据。

模型概览的数字来自所选调用，不是整局累计。输入支持 `input_tokens` / `prompt_tokens`，输出支持 `output_tokens` / `completion_tokens`。零值正常显示，未报告的用量显示“未报告”，不根据正文长度估算。缓存与推理用量单独展示，不再次加进输入/输出总数。小摘要会缩写大数字，悬停可查看精确值，完整模块显示精确数字。

已完成调用使用日志中的 `timing.duration_ms`，缺失时显示“未记录”。未完成的实时调用根据请求时间更新已等待时长。历史回看只显示请求到所看位置末次输出记录的间隔，不随现在的时间继续增长，也不把它称作首字延迟或输出速度。切换调用或历史位置时，统计随记录一起切换。所有信息来自已记录数据，不额外请求模型或计算评分。

顶部任务状态、工具预算和“运行信息与产物”始终描述实时任务。中间的“历史局面”只描述当前观看位置。评分只使用截至该位置已记录的数值，不把回合末的评分提前显示到回合开始。结束回合后的快照可能已经进入下一回合，界面会明确提示。

在单局内部点击“返回总览”再展开模块，会保留模块的筛选、选中对象和滚动位置。总览与所有已打开模块共用同一观看快照，切换历史回合会一起更新，缺失的旧对象不会继续显示。只有用户展开过的完整模块才会挂载，隐藏的模型模块不会因保留输入展开状态而自动读取新调用的完整输入。

进入专注视图再返回会保留每路观看位置。观看位置只保存在页面内存中。刷新后恢复观战列表并回到实时位置，不将模型正文或完整快照写入浏览器存储。

服务端增量索引事件文件，按单次回合尝试加载历史，流式文本碎片折叠为调用内容。该读取过程不改变 runner 或冻结协议。详细观战默认使用当前执行的事件，从恢复检查点开始。通过“整局检索”或对象轨迹可定位到续跑之前的行动，定位后回合选择也切换为整局归档中的尝试。旧执行的原始日志仍保留在对应任务目录中，“打开完整回放”入口继续保留。

## 整局检索与对象轨迹

单局“行动时间线”提供“所选回合”和“整局检索”两个范围。“整局检索”先在工作区顶部展示经营概览，按招募、天赋购买、装备制作、穿戴与卸下、经验分配、战术配置、结束回合和其它操作统计尝试次数与已确认成功次数。一次操作即使影响多个对象也只计一次，已回滚的成功操作不计入已确认成功。概览始终统计已记录的整局，不受下面的关键词或回合范围影响。

点击概览的类别、状态或总次数，会清除当前筛选并查看对应的全部已记录操作，不改变观看位置。点击具体记录才定位到当时局面。用户也可以在下方组合搜索、具体操作、状态和回合范围。概览的失败、未提交和回滚计数可能重叠，不能将这些状态相加。读取中或读取失败且没有缓存时显示未知，不显示虚假的零。仅有当前执行阶段日志时，标题和覆盖范围都会明确提示。概览不包含查询与试算次数。怪物刷新工具中 `preview=true` 的记录也按查询处理，不计入经营次数，仍可在所选回合的查询记录中查看。

概览横跨整个工作区，下方仍为检索结果与所选行动详情。桌面不增加概览内部滚动，手机按整页纵向查看。

整局检索可按对象名称或 ID、操作类型、状态和回合范围筛选，每页最多显示 40 条。每条结果标明所属回合、该次尝试中的操作序号、执行结果和实际变化，并提供关键输入预览。点击结果会暂停观看跟随，定位到真实历史结果帧，不暂停运行任务。原始事件和模型记录按需从对应日志读取，不能用归档字节位置去读取当前执行阶段的日志。

所选回合与整局检索不再将操作摘要统一裁成两行。选中行动后，先显示具体结果摘要，输入仍常驻在靠上位置，不移到底部或整区收起。普通参数紧凑排列，字段原名与原值同行，减少重复留白。派遣等对象列表以一行一组的表格展示，技能顺序保留输入顺序，备忘保留原文。零、false、空列表和 null 不会被当成缺失参数。明确记录的空对象显示“无输入参数”，日志未记录时明确提示，不能从执行结果反推。

业务返回与实际局面变化分开展示。招募、制作、升级和配装展示已记录的成员、实际产物、实例、属性和解锁项。队伍、库存、候选、配方等查询直接展示本次返回的表格，不用当前局面替代查询结果。表格每页最多六条，可在已经返回的数据中筛选，点击名称可展开此条记录的可读字段，不额外发起工具查询。战术配置以真实返回的技能顺序和停用项为主，不在其它操作中重复铺开未改变的战术。战斗展示胜负和已记录奖励，未记录的耗时不留整列空占位。模拟和未来查询明确标注，不作为实际收益。原始 JSON 继续作为调试入口，不承担常规结果阅读。

所选回合与整局检索共用只读业务结果投影，仅从显式返回或确实记录过的前后快照提取变化对象及明确操作目标的实际状态。成功但状态未变的操作也可查看目标状态，不按请求或配方猜测产物，不重新执行游戏或评分。索引不复制整份局面和完整战斗过程。缺少结果或变化数据时说明记录不足，不将未知视为成功或零。多路观战仍保留有界短预览，完整参数和业务返回进入单局查看。部分旧日志只在工具调用中记录参数，展示层和整局索引会按同一调用关联保留这些输入，不修改结果帧、原日志或历史定位。参数继承与业务返回投影的后端更新需要等当前任务结束后重启服务，无需改写现存日志或重跑整局。

天赋、制作配方和具体装备的详情顶部提供“本局轨迹”。天赋摘要标出已确认的解锁回合，配方摘要统计已确认制作次数和首次制作回合，装备摘要显示已记录的制作回合。展开后可查看相关制作、穿戴、换装和卸下记录。相同名称的不同装备按实例 ID 区分，回滚分支中复用 ID 的记录会保留回滚标记，不计入成功次数。

轨迹使用整局追加的 `trace.jsonl`，覆盖续跑前后，索引只保存行动字段与对象引用，不保存完整提示词或每一步的完整局面。首次读取后只索引追加内容，最多缓存四份日志索引。回合结束的记录标为已提交，尚未提交的操作和失败操作单独标注，回合重试或续跑丢弃的分支标为已回滚。续跑按实际恢复回合判断，即使此前已有回合完成事件，没有进入恢复检查点的分支也会回滚。检查点保存失败时会提示记录可能未进入恢复点。统计成功需要工具返回成功且所属回合已提交，并且没有在后续恢复时被回滚。

对象轨迹展示整局记录，可能晚于正在查看的历史快照。后续回合会有标记，只有点击定位才切换当前观看位置。没有记录不能证明没有发生，也不能推算购买或制作时间。整局原始日志缺失时，页面会明确提示只覆盖当前运行阶段，不重建局面、调用模型或补评分。首次启用轨迹接口时，需要等正在运行的任务结束，再按原参数重启 Web 服务。仅更新概览等前端内容时，重新构建并刷新页面即可。

## 曲线对比

左侧“曲线对比”是统一入口，最多比较四个 run。运行列表和历史存档多选后可点击“对比选中曲线”，实验批次也提供入口。单局和侧栏标题区的曲线按钮带入当前 run，多路观战顶部的“对比当前观战曲线”带入正在看的所有 run。CLI 存档同样可以参与曲线比较，但不能实时观战。返回原工作区会保留已保存的观战位置。

三张图共用真实回合横轴和定位回合。悬停或按图表方向键可联动数值表，差值相对图例中首个 run，数值最多保留四位小数。可调整回合范围，点击“全程 / 跟随最新”恢复完整范围和最新回合。刷新页面会恢复所选 run，资源口径与回合范围恢复默认值。

| 指标 | 默认口径 | 切换到“结算后余额” |
| --- | --- | --- |
| 经济 | 累计讨伐金币奖励 | 结算及恢复后的金币余额 |
| 经验 | 累计讨伐经验奖励 | 结算及恢复后的未分配经验池 |
| 战力 | 已记录的正式 Rank Score | 口径不变 |

累计讨伐收入不包含开局持有量，不扣招募、制作和经验分配，不代表当前余额。曲线使用成功完成回合的记录，失败及回滚尝试不作为新的结算点，试算评分不代替正式评分。缺失回合断线，未知数值不补零。缺少奖励记录时，后续累计收入保持未记录，不用已知后续奖励猜补缺口。旧续跑没有结算快照时，只允许紧邻下一回合的开局快照补充上回合余额，不使用可能已被操作改变的最终局面。

这里显示全程已记录的曲线，不随历史观战位置回退。同一存档的续跑使用权威回放中的完整历史，不把各次执行的累计值相加。不同协议、数据、种子或回合上限会给出提示，旧存档缺条件资料时明确标为未核实。图线和差值仅供并列查看，不生成跨规则排名。

浏览器只获取轻量数值投影，不下载完整回放。服务端按文件修改时间缓存投影，运行中的选中 run 每 2.5 秒读取一次，检查点和终态变化会主动同步。回放暂不可读时可保留上次成功投影并标注过时，存档写入失败也会提示。可以手动刷新。CLI 目录不做定时轮询，进入页面或手动刷新时可更新列表。

曲线读取不调用模型、不重算评分、不重建局面，也不修改原存档。本功能新增后端接口。更新已有服务时，应等待当前任务结束后按原参数重启 Web 服务，不能只刷新前端。

## 停止、关页与恢复

- **关闭、刷新浏览器或网络断线**：不停止任务。
- **取消排队**：任务不会启动，也不会发出模型请求。
- **停止运行**：先请求协作退出。界面保持“停止中”，直到进程退出被确认。阻塞超过 8 秒后强制结束进程。
- **强制停止**：只能保证使用最近成功写入的检查点恢复，不能保证保存尚未完成的模型响应或当前回合。
- **关闭服务**：停止受控任务。服务异常退出后，工作进程检测到控制管道断开，也会退出，避免无限期留在后台。
- **重启服务**：历史状态保留，未确认结束的任务标记为中断，不自动重新发出模型请求。可以再次选择已保存的 API 配置手动续跑，不必重新输入密钥。

在“历史存档”中选择未完成存档并续跑。续跑沿用归档中的评测参数，仍由原 runner 校验协议。未完成回合可能回滚。可重新选择模型接口并提供凭证。

工作台对自己的服务目录和受控运行归档使用操作系统文件锁。同一份归档不能同时由多个工作台进程写入。CLI 和旧调试接口不参与这套锁，续跑前必须自行确认没有 CLI 或旧调试任务正在操作相同存档。

“历史存档”合并工作台的终态摘要与 `runs/llm/` 中的存档，同一 run 不重复展示。受控 run 以工作台当前状态为准，排队或执行中不同时出现在历史页。CLI 归档按只读方式接入，存档中残留的 `running` 不证明对应进程仍存活。工作台不提供对外部 CLI 进程的停止操作。其他目录中的 CLI 运行目前不自动发现。

## 已知限制

Windows 并行验收曾观察到两个同模型任务取得相同的时间戳，生成同名存档目录，其中一个任务以 `WinError 183` 启动失败。已有目录不会被覆盖，失败记录仍可在历史中查看。当前存档目录分配逻辑尚未修复，本轮界面调整没有修改该逻辑。

## 凭证与存储

- 未保存的显式 API Key 只保留在调度器内存中，通过工作进程标准输入传递，不出现在进程命令行、工作台任务配置或浏览器模板中。
- 明确保存的 API 配置将密钥存入当前系统用户的凭证库，元数据保存在 `runs/.workbench/api_profiles.json`，不保存明文密钥。浏览器模板只记录配置 ID。
- 模型服务地址不允许包含用户名、密码、查询参数或 URL 片段，请使用独立的 API Key 字段。
- 模板、主题、筛选、关注列表和面板宽度保存在浏览器本地。保存模板不会保存 API Key。
- 调度设置和任务摘要保存在 `runs/.workbench/`。每个任务目录包含 `state.json`、`events.jsonl` 和 `stderr.log`。运行产物继续保存为 `runs/llm/<run_id>/replay.json` 和 `trace.jsonl`。
- 模型正文、提示词和工具结果可能包含敏感数据，分享日志和归档前仍需检查。

这是可信本机工具，不提供用户认证。不要直接暴露到公网，也不要用多个 Uvicorn 服务进程共同管理同一个工作台目录。
