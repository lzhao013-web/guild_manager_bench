# 运行工作台

工作台在本机 FastAPI 服务中管理任务。浏览器只提交操作和读取状态，不持有 runner 的生命周期。游戏引擎、LLM 适配器和冻结的 `full v1` 文件保持不变。

## 启动

需要 Python 3.11+、uv 和 Node.js 22.20+。从仓库根目录执行：

```powershell
uv sync --all-groups
npm ci
npm run build
uv run guild-manager serve --preset full
```

打开 <http://127.0.0.1:8000/>。前端源码更新后重新运行 `npm run build`。第一次构建必须在服务启动前完成，没有构建产物时首页会提示构建步骤。

构建保留旧的带 hash 的 JS 和 CSS 分包，供已打开的页面继续按需加载。不要在更新时直接清空 `web/workbench/dist`。需要回收旧资源时，先关闭仍使用旧界面的标签页，再在维护窗口清理并重新构建。

工作台带内容哈希的 JS/CSS 使用一年期不可变缓存。首页、工作台 HTML 和未按此命名的静态资源使用 `no-cache`，允许浏览器保存后通过 ETag 重新验证，资源未变时返回 304。公共字体路径不套用不可变缓存，避免更新同名文件后仍使用旧字体。缓存响应头的修改需要重启后端服务才能生效。

曲线、历史和观战页面加载或渲染失败时，只在对应工作区或观战面板显示错误，不卸载导航和其它正常面板。可切换到其它工作区，也可点击“刷新页面”重新加载当前地址。页面不会因加载失败自动循环刷新。刷新浏览器不会停止后台运行任务，临时回看位置仍按原有刷新行为重置。

人工操作位于 `/legacy/?mode=manual`，原来的 `/?mode=manual` 和 `/?watch=1` 仍有效。旧 LLM 调试页位于 `/legacy/`，它仍使用原来的连接式调试接口，不具备新工作台的任务管理语义。原来的 `/replay/`、对照复盘、经营画像和 `/leaderboard/` 保留。

## 界面外观

工作台使用 MiSans 显示界面文字，使用 JetBrains Mono 显示数值与日志。字体随应用本地提供，不要求本机安装，也不依赖外网 CDN。MiSans 保留官方 unicode-range 分片，仅按页面文字加载相应文件，两套字体均使用 `font-display: swap`。“调度设置”中的折叠项“字体授权”提供来源和授权说明，完整协议随构建产物保留。两套字体遵循各自授权，不使用项目代码的许可代替字体许可。维护字体资源时可执行 `python -X utf8 web/workbench/prepare_fonts.py`，随后重新构建工作台。

工作台采用固定的字号与间距，主要正文使用 13-14px，运行列表、观战摘要和曲线中的辅助信息保留 12px，不再提供密度切换。多路观战空间不足时整体滚动，不通过继续缩小文字强行塞进一屏。浅色、深色和跟随系统的主题选择保持不变。

控件状态使用 120ms 的颜色过渡。切换所选行动时，详情区以 160ms 淡入并轻微上移，选中的行动和整局检索记录显示一次短暂的描边高亮。模型推理展开使用相同的详情过渡。这些效果不改变数据、布局或定位逻辑，系统开启“减少动态效果”时全部停用。

界面仅保留操作反馈、数据缺失与过时状态、危险操作后果和必要的使用说明。曲线和历史不再展示比较限制声明，观战与行动详情不再反复解释只读、不重算或不推测。跨版本事实仍用短标记显示。服务端返回的已知提示由前端统一转换为简短文字，删除比较声明时保留同一响应中的保存或读取失败信息，无需为此重启服务。原始日志与模型输出不改写。旧版对照复盘和经营画像遵循相同规则，保留具体缺失项和禁用原因。成本图保留运行次数、估算费用及计价范围，不附加统计结论免责声明。

## 创建与管理实验

可先在左侧“API 配置”保存常用连接，再在每个模型行直接选择。支持从命令历史导入，以及查询服务端模型目录。密钥保存在系统凭证库，配置列表不返回密钥，编辑窗口可直接查看和修改 Key。详见 [API 配置与模型目录](api-profiles.md)。

1. 选择“新建实验”，设置 preset。
2. 添加一个或多个模型，选择 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 或 Google Gemini 原生 API。模型、服务地址和 API Key 留空时使用服务端环境配置。
3. 可填写多种推理强度、多个游戏种子和重复次数。工作台展示展开后的任务清单，一次最多创建 64 个 run，待处理任务总数最多 128 个。重复不会自动改变种子。
4. 确认清单后加入队列。在“调度设置”中配置全局并发和每个服务地址的并发，均为 1 到 8，默认均为 2。降低上限不打断已启动任务。服务端点并发不等于 API 请求速率限制。

每个 run 使用独立工作进程。工作台在该进程中将评分执行器限制为单线程，避免多个 run 各自创建整机规模的评分进程池。评分函数、输入和协议指纹不因这项调度设置而改变，CLI 的执行方式也不受影响。

运行中心只展示排队中、启动中、运行中和停止中的 run，按固定顺序排列，状态变化不会自动重排。支持搜索、状态筛选、关注、批量停止、曲线对比，以及最多四路观战。已完成、失败和已中断的 run 出现在“历史存档”，未生成存档的启动失败和取消排队也会保留。详情页包含队伍摘要、评分曲线、行动、模型调用、诊断、配置和产物。模型推理只展示 API 实际提供的文本或摘要。

顶部“执行中”统计和筛选均只包含启动中、运行中与停止中的任务，不包含排队任务。“执行中”“等待队列”“存档异常”三个按钮再次点击时均恢复所有状态，搜索条件保持不变。

同一存档的首次运行和多次续跑，在界面上始终作为一个 run。状态和统计使用当前执行的数据，不重复累加续跑时恢复的累计用量。后台仍保留原批次字段以读取旧记录，界面不再展示实验批次、批次筛选或模型模板。续跑不新增用户可见的 run。原执行 ID 的链接、关注和观战选择会定位到同一个 run 的最新执行。除用户确认删除外，内部执行记录和日志仍保留，不删除或改写已有历史。

页面打开期间，run 结束时会出现可关闭的结果通知，失败使用警示提示。活动列表会移除这个 run，但已经打开的详情或观战面板不会突然关闭。运行中心仅在没有活动任务时显示“最近结束”区域，直接从已有受控运行中按结束时间取最近五个，显示身份、状态、已记录评分和结果入口。只要还有排队、启动、运行或停止中的任务，就不显示该区域，搜索或状态筛选无结果也不例外。未记录结束时间时按最后更新时间排列。刷新页面仍能查看，不依赖本次页面打开期间是否收到结果通知。续跑中的运行移回活动列表，顶部通知仍可单独关闭。没有活动任务时收起无效筛选和零计数，保留简短的空闲说明及最近结果。首次使用与筛选无结果使用各自的说明和操作，不显示加载样式图标。历史页支持查看详情、续跑，以及选择最多四个受控 run 回看。

运行列表、历史、侧栏、观战和曲线显示短 ID，悬停可查看完整标识。受控 run 沿用首次执行的身份，续跑不更换显示标识。CLI 短 ID 取存档时间戳片段，不使用同名模型的公共尾缀。列表可按 ID 搜索。观战和曲线的添加入口可搜索名称、模型、preset 或 ID，支持方向键、回车选择和 Esc 关闭。搜索结果超过 50 项时先显示前 50 项，输入关键词后仍可找到其余记录。已选项不重复显示，每个工作区仍最多选择四个运行。

历史页提供独立的 preset 筛选，可与关键词和状态组合使用。选项来自已记录的受控 run 和 CLI 存档，缺少 preset 的存档可通过“未记录 preset”筛选。直接点击表头的名称、Preset、当前状态、进度、Rank Score、耗时、Token 或创建时间排序，再次点击同一字段切换升降序。当前排序列显示方向箭头，并提供键盘操作和屏幕阅读器排序状态，不再单独提供排序下拉框。默认按创建时间从新到旧，数值列首次点击优先降序，名称、Preset 和状态首次点击优先升序。创建时间以本地时区显示，原始时间可通过悬停查看。未知排序值始终排在末尾，零分和第零回合正常参与排序。受控 run 使用当前行的值，不使用旧存档中的过时评分。筛选和排序只影响浏览器列表，不修改存档或改变 run 的归并规则。

运行中心在回合列旁显示已记录的模型调用累计耗时。历史列表同时显示这一耗时，以及 API 已报告的输入、输出和总 Token。耗时不包含工具执行、评分和中断等待，总 Token 为输入与输出之和，不重复加计缓存或推理 Token。单侧用量缺失时保留已知明细，总量显示“未记录”，不把未知值当作零。旧工作台记录未保存累计耗时时，从对应存档的响应记录读取。列表读取复用存档摘要缓存，不改写原存档或额外调用模型。服务端新增统计字段需要在当前任务结束后重启服务，再构建并刷新页面。

历史行保留简短的“跨版本”标记，不再显示比较限制横幅。短 ID 与存档标识并排显示，长标识悬停可查看完整值。数值列右对齐，保持等宽数字和可读字号。

历史列表为受控 run 保留“查看详情”主入口，CLI 存档使用“查看曲线”主入口。操作列固定在表格可见区域的右侧，首次进入即可使用主入口和“更多”，无需先横向滚动。其余字段仍可横向查看，原有列宽偏好保留。续跑、指定回合重跑、重新创建和删除等次要操作位于每行的“更多”菜单。失败原因先显示简短摘要，点击展开后查看原始错误。进度保持单行，长存档标识可悬停查看完整值。这些调整不改变排序、筛选和操作目标。

### 删除存档与运行记录

历史行的“更多”菜单提供“删除存档”。未生成存档的终态任务提供“删除记录”。二次确认后永久删除完整存档目录及关联的已结束工作台执行目录，包括回放、检查点、源代码快照和日志。同一存档的多次续跑一起清理，已有独立重跑分支不连带删除。删除后清理界面中的关注、观战、选择、通知和曲线引用。

勾选当前筛选结果后可点击“删除选中”。确认框固定本次名单，逐项调用原删除接口，不保证整批全部成功或全部回滚。成功项移出列表并取消勾选，请求失败的项保留原选择并显示各自原因，重试不会再次提交已成功的项。执行期间不能关闭确认框。选中项含被运行或续跑占用的存档时，需先取消勾选占用项；执行过程中出现的新占用仍由服务端拒绝。

排队、启动、执行、停止中的任务及其引用的源存档禁止删除。删除与运行、恢复共用目录外的操作系统锁，并检查原有目录内锁。先将整组目录移到各自存储根目录的 `.deleting/<操作编号>/` 下，再清理文件。移动失败会尝试移回原目录，尚未完成移动时不移除任务记录。移动成功后，即使文件清理失败，服务重启也不会把记录重新载入。清理失败返回错误，残留文件需要在解决磁盘权限或占用问题后手动清理，不提供回收站或撤销。

CLI 与旧调试接口不参与工作台锁。删除外部存档前必须自行确认对应进程已经停止，不能仅凭存档中的 `running` 或终态标记判断进程是否存活。删除接口限制同源请求和存储目录边界，不跟随存档符号链接或 Windows junction。

工作台只保留排行榜的外部页面入口，移除人工操作、旧回放、经营画像、旧版两局对照和调试页跳转，保留原始 JSON 下载。旧路由和文件仍可按原地址访问，不在本次调整中删除。重复的页脚和页面介绍不再展示，错误、跨版本风险和删除确认仍保留。

任务状态和执行阶段分开展示。页面可见且有排队或执行任务时，浏览器按 1 秒间隔读取摘要。没有活动任务时改为 5 秒间隔，仍会发现其它页面提交的新任务，也可点击“立即刷新”。实际请求频率还受响应耗时影响。连接失败时保留上次成功读取的数据并标注离线，重新连上或刷新后从服务端恢复任务列表。

`GET /api/workbench` 只返回运行元数据，不再携带 `observation`。创建批次和停止任务的响应使用同一摘要结构。侧栏队伍和资源复用选中任务的 `/api/workbench/jobs/{job_id}/watch` 回合快照，不从列表摘要读取局面。服务端内部状态和已保存日志不变，评分仍只展示已记录的正式 `rank_score`。接口更新需要在当前任务结束后重启服务，并构建、刷新前端。

阶段和运行耗时由独立文本组件计时，不再每秒驱动整个工作区更新。页面进入后台时暂停这些时钟，返回前台后按实际时间恢复。

运行列表侧栏的原始模型与诊断日志用字节游标增量读取，保留最近 600 个事件。侧栏行动与详细观战按回合读取当前工作任务的完整事件历史，不受该窗口限制。侧栏展示当前回合，其他回合通过专注视图选择。完整记录保留在任务事件文件和原运行归档。

## 详细观战

在总览中选择任务并点击“专注查看”，或多选任务后点击“观战选中”。单局观战默认进入综合总览，同时展示编队、怪物、装备、招募、公会发展、最近行动和模型输出摘要。点击模块标题或摘要中的对象后，模块在同一工作区完整展开，不跳页、不以弹窗查看核心详情。顶部可一键返回总览或直接切换模块，运行状态与回合定位始终保留。多路观战使用专用摘要面板，不再把完整单局详情缩小后放入格子。每路同时显示编队血蓝、怪物、最近有效行动或失败、模型摘要和已记录评分。编队最多显示 6 位，低生命成员提前，怪物最多显示 4 个并提供其余数量入口。点击人物、怪物、行动入口或模型摘要，直接进入该 run 的对应单局模块。返回时保留观看位置。

多路模型区显示一条本次调用信息和最多一行最新正文，等待响应时保留调用信息，不再用模型框撑满剩余高度。空出的区域用于招募候选、天赋与升级、装备与制作、经营进展。预览展示服务端记录的价格、资格和缺口，优先展示满足条件的对象，不按推测的强弱排序。制作摘要先展示满足条件的配方，按当前金币费用从高到低排列，再展示闲装和缺资源配方。配方没有独立阶级字段，不根据名称推断阶级。天赋摘要按可解锁、已记录阶级和金币费用降序排列。闲装仍保留独立计数入口。点击候选、节点、装备或配方可直达完整详情。

预览按实际剩余面积分级：大面板展示对象、费用、效果和条件，小面板保留机会计数、最近操作与重点失败。每类最多展示 8 项，空清单不生成空白卡片，旧快照缺字段会标为未记录。编队已满时收起招募卡，将空间优先用于升级和装备，候选仍可在单局招募模块查看。经营进展只使用当前观看位置之前的行动，展示具体操作、失败和查询数量，不再显示局部曲线。多路曲线通过顶部“对比当前观战曲线”统一查看，不额外请求模型生成摘要。

底部保留回合选择、步骤进度条、上一步、下一步和跟随开关。拖动进度条会冻结到对应历史位置，不停止任务。运行状态、阶段耗时和工具预算描述实时任务，资源、评分与局面摘要来自当前观看位置。多路面板只挂载有界预览，不挂载完整日志、模型输入、装备查看组件或天赋图，完整内容在单局模块中查看。桌面按剩余视口分配网格，三路采用三列，四路采用两行两列。手机采用单列浏览，较矮窗口保留网格并整体滚动，不给每个摘要区域再加滚动条。

- **定位回合**：按回合及重试次数选择记录。失败后回滚的尝试单独保留，并标注“已回滚”。
- **查看行动**：最近行动、完整时间线与多路摘要使用同一套表达。标题保留具体对象和操作，资源消耗、装备归属、属性、天赋和战术变化单独展示。优先使用原事件的中文摘要与变化清单，旧记录缺清单时只比较已保存的前后快照，不推算额外收益。
- **展开时间线**：一次工具调用及其结果合为一条操作。尚未返回时标明执行中，连续查询折叠为一组，运行事件集中收起。失败、重试和回滚提示仍直接显示。没有经营操作时明确提示目前只进行了查询。操作详情列出具体变化与真实讨伐双方及结果，原始事件和参数按需读取。实时跟随时可查看截至当前位置的最近操作详情，不因打开模块而暂停任务。旧记录缺少战果字段时标为结果未记录。
- **点击行动**：队伍、资源和模型调用一起定位到操作的真实结果帧。上一步和下一步仍按原始位置移动，保留调用之前、等待结果、结果之后的观看位置。已回滚尝试中的操作会标明不再生效。
- **从工具定位推理**：在单局工具详情点击“查看对应模型推理”，切换到所属模型调用，在正文前展开并定位 API 推理区。普通模型查看仍以正文优先。顶部“返回该工具”保留原行动及检索条件，只冻结观看位置，不停止任务。所选回合和整局检索都支持，包括续跑之前的记录。一次响应包含多个工具时，说明它们共享本次响应的推理，不推断每个工具的独立思考区间。旧日志缺少模型关联时禁用入口，不能跳到附近的其它调用代替。对应调用没有可读推理记录时明确提示，不以正文、参数或重新生成的内容冒充。手动选择其它模型调用后退出关联定位。
- **暂停跟随**：冻结已经读取的局面与输出，任务继续执行。后续事件不会覆盖当前观看位置。
- **返回实时**：活动任务追上最新记录。有新事件时按钮会提示。已完成任务显示“最终局面”，失败和中断任务显示“最后记录局面”，不再提供“暂停跟随”。仍可按回合和步骤查看历史，并通过“返回最终局面”或“返回最后记录局面”回到末次记录。结束不会自动退出正在查看的历史位置。
- **查看编队**：总览显示全部成员，生命低于上限 30% 的成员优先，保留角色缩略图、等级和真实生命/法力。四人编队在常规宽度下排为 2×2，宽卡片排为 4×1，不再固定排成 3＋1。展开编队后，通过对象选择框或左右按钮切换成员，在模块内部完整查看属性、装备槽位和技能。点击“收起对象详情”可回到该模块的集合视图。
- **查看装备与技能**：装备按真实槽位围绕角色排列，区分空槽、已穿戴和被其他装备占用。桌面端将选中装备的属性与技能放在槽位图旁边，还可直接定位到同槽库存。攻击、防御和速度优先显示，生命与法力上限保留在状态条中，开启“对比基础”后也会显示这两项的属性差值。装备技能默认显示名称，展开后查看完整效果。
- **查看怪物与招募**：怪物和候选以图鉴卡展示，点击查看详情。怪物以独立的阶级标签和身份标签显示，精英使用星形图标，首领使用皇冠，固定挑战使用旗帜。总览和多路始终展示标签，不依赖名字前缀或悬停。完整属性位于怪物模块和详情，不推测剩余生命或胜率。招募卡只展示当前条件，不执行招募。
- **查看库存**：装备库支持搜索、槽位和穿戴状态筛选。
- **查看制作**：装备模块内可切换到制作配方，按名称和成品槽位筛选。详情显示当前金币费用、原价（快照有记录时）、材料需求与持有量、服务端报告的缺口、成品属性和技能，并可返回同槽库存。所有入口只读，不执行制作。
- **查看天赋路线**：高级天赋横向按真实分支、纵向按已记录层级排列。没有分支标记的旧版升级按前置深度排列，不虚构分支。点选节点后持续突出全部前置路线，实线箭头表示前置，红色虚线表示互斥。节点区分已解锁、可解锁、缺资源、缺前置和互斥锁定，点选详情显示完整金币、经验、材料费用、服务端报告的缺口和关系入口。搜索按名称或 ID 匹配，回车逐个定位，其他分支不会被删除。可拖动空白处平移、缩放、定位选中节点或适应全图。首次缩放保留可读字号，返回模块时保留搜索、缩放和画布位置。
- **查看材料**：顶部保留少量摘要，完整材料以弹出网格展示，避免长文本挤压主画面。所有内容来自所选快照，缺失字段明确显示未记录。
- **查看模型**：总览、多路摘要和完整模型模块都显示本次调用的状态、输入/输出 Token 和耗时。完整模块还显示已报告的缓存 Token、推理 Token、工具调用数，以及模型、接口和配置强度。正文保留在信息条下方，完整输入与原始响应按需读取。推理区仅展示 API 实际返回的文本或摘要。
- **查看战斗**：展示工具返回的战果与奖励。模型已经查询过的战斗日志可以展开查看，不额外执行工具、请求模型或重新模拟。

桌面端压紧运行信息与底部观看控制，将主要空间留给编队、最近行动和怪物。桌面总览保留对齐网格，同排卡片等高，并利用可用高度分配空间。留白在卡片内部，不使用左右独立堆叠的瀑布流。总览卡片不设置内部滚动条，列表按内容区实际宽高展示能够完整放下的条目，展开后查看全部。已知为空和快照未记录仍分别说明。普通模块使用浅边界，角色和怪物的状态描边不变。最近行动优先显示具体操作、失败和重试，不用“请求模型”或“运行完成”替代经营内容。连续查询不会刷走这些记录。装备、招募、怪物、升级和最近行动不再固定截取两项或六项，展示数量随卡片空间调整，优先展示未穿戴装备、满足条件的候选和可解锁升级。模型正文在卡片剩余区域内展示，展开后查看完整记录。小屏幕使用自然高度和页面纵向浏览。

最终局面保留最后一次结算后的真实队伍、资源和已记录评分。游戏结束快照的总览收起怪物和招募候选，剩余五张卡片重新排成对齐网格，不用旧回合内容填补空位。回看结算前时，这两个模块按当时快照恢复。从已收起的模块返回总览时，键盘焦点落在编队入口。结算行动的战斗统计只展示一次，历史行动时间保留完整时分秒。

### 状态边框

单局总览、完整卡片、多路摘要和详情立绘使用同一套轻量描边。边框、内侧高光和角部强调不增加卡片尺寸，也没有持续闪动。键盘焦点使用独立外轮廓，详情立绘保留选中描边，不覆盖原本的状态颜色。

冒险者以当前观看快照的生命为主：满血青绿、受伤琥珀、生命低于上限 30% 红色，生命为零时显示灰色虚线和“倒下”，不表示永久死亡。低生命和倒下保留图标，完整卡片也显示状态文字。法力上限大于零且当前法力为零时单独显示耗尽标记，不覆盖低生命框，无蓝职业不误报。

普通怪物按已知 T 阶级着色，精英紫色、首领金色、挑战红色，身份优先于阶级。原有文字标签和图标保留，未知分组使用中性边框。怪物快照没有当前生命时，不根据生命上限伪造受伤或倒下状态。

### 怪物分组与模型调用统计

怪物 T1/T2/T3 依据本机对应 preset 的 `monsters.yaml` 原型分组：首次解锁回合 1—7 为早期 T1，8—17 为中期 T2，18 起为晚期 T3，包含 24、26、28 回合出现的晚期变体。按原型的 `min_turn`，不是当前回合或怪物数值判定，所以后期出现的史莱姆仍是 T1。`challenge` 单独显示为挑战，不冒充普通怪物的首领身份。分组只在界面投影中使用，不改写原始观测或归档。日志没有阶级字段时使用当前本机原型表补充显示，原型未匹配、preset 已移除或原型文件暂不可读时标为阶级未知，不猜测。修改原型文件后，后续读取会更新分组元数据。

模型概览的数字来自所选调用，不是整局累计。模型、接口和强度标为“当前 run 配置”，不作为续跑之前旧调用的配置记录。输入支持 `input_tokens` / `prompt_tokens`，输出支持 `output_tokens` / `completion_tokens`。零值正常显示，未报告的用量显示“未报告”，不根据正文长度估算。缓存与推理用量单独展示，不再次加进输入/输出总数。小摘要会缩写大数字，悬停可查看精确值，完整模块显示精确数字。

已完成调用使用日志中的 `timing.duration_ms`，缺失时显示“未记录”。未完成的实时调用根据请求时间更新已等待时长。历史回看只显示请求到所看位置末次输出记录的间隔，不随现在的时间继续增长，也不把它称作首字延迟或输出速度。切换调用或历史位置时，统计随记录一起切换。所有信息来自已记录数据，不额外请求模型或计算评分。

顶部任务状态和“运行信息与产物”描述当前任务。执行阶段与工具预算只在任务活动期间展示，终态不再重复显示“已结束”或底部结束说明。中间的“历史局面”只描述当前观看位置。评分只使用截至该位置已记录的数值，不把回合末的评分提前显示到回合开始。结束回合后的快照可能已经进入下一回合，界面会明确提示。

在单局内部点击“返回总览”再展开模块，会保留模块的筛选、选中对象和滚动位置。总览与所有已打开模块共用同一观看快照，切换历史回合会一起更新，缺失的旧对象不会继续显示。只有用户展开过的完整模块才会挂载，隐藏的模型模块不会因保留输入展开状态而自动读取新调用的完整输入。

进入专注视图再返回会保留每路观看位置。观看位置只保存在页面内存中。刷新后恢复观战列表并回到实时位置，不将模型正文或完整快照写入浏览器存储。

服务端增量索引事件文件，按单次回合尝试加载历史，流式文本碎片折叠为调用内容。该读取过程不改变 runner 或冻结协议。详细观战默认使用当前执行的事件，从恢复检查点开始。通过“整局检索”或对象轨迹可定位到续跑之前的行动，定位后回合选择也切换为整局归档中的尝试。旧执行的原始日志仍保留在对应任务目录中，原始回放可在配置与产物中下载，不跳转旧回放页面。

## 整局时间线

在单局“行动时间线”中选择“整局时间线”，可从头阅读一个 run 每回合的操作。运行列表侧栏也提供“整局时间线”按钮，直接进入该视图。原有“所选回合”和“整局检索”保留，分别用于逐条查看与精确检索。

默认展示紧凑的整局进程表，不再从头铺开每条操作卡片。每回合只占单行，根据工作区实际宽高分为1到2列，先从上到下读完一列，再看右列。每列重复同一表头，回合、主要操作、胜/负、金币奖励、经验获得量和战力Δ分别对齐，不把多组指标塞进同一格或叠成两层。桌面行高按可用高度在20至24像素间调整，尽量在同一屏覆盖整局，窄屏允许纵向滚动。常规操作使用“招募×3 / 制作×1”等可读名称；发生全局升级时，主表优先显示升级名称，其余操作和查询、预览、备忘录、重复提交的辅助调用次数收在悬停摘要及回合详情中。失败用回合旁的感叹号标记。文字过长时保留行高，通过悬停摘要或点选回合查看完整内容。

- **全局升级**：主表直接突出解锁名称，选中回合后再展示已记录效果、资源消耗及属性变化，不从当前配置补推历史收益。
- **回合结束**：主表显示胜负、金币奖励和本回合获得的经验。“经验获得”汇总已记录的讨伐经验奖励，不扣除培养、天赋等支出，也不把解雇返还计为讨伐获得量；它不是经验池余额变化。主表与回合详情使用相同口径，不依赖资源变化清单是否完整。缺失任一场经验奖励时显示未知，明确零奖励或零场讨伐正常显示0；已回滚尝试不展示有效收益。选中回合后可查看实际讨伐双方、材料及全部结算变化。
- **批量方案**：成功提交的真实子步骤计入主表的操作次数和升级名称，回合详情中再按顺序列出。子步骤共用原子提交的真实游标，点击后查看所属方案，不伪造中间局面。重复提交不重复展示收益，试算不作为实际操作。
- **重试与回滚**：同一回合仍只占一行，主表采用最近一次未回滚尝试，并标明尝试次数。旧尝试在该回合详情的选择框中查看，不混入主表的升级和收益。尚未提交、失败、中断和无工具记录的回合仍保留。“战力Δ”显示当前回合相对紧邻上回合的正式 Rank 差值，两回合均须已完成且未回滚。首回合、缺失记录、不相邻或未提交时显示未知，不拿试算评分、旧 Arena 分或跨回合差值补齐。零分和零变化正常展示，负变化保留符号。详情仍显示该次尝试已记录的正式 Rank Score。

点击行或通过顶部选择框选中回合后，才挂载该回合的操作详情。详情使用覆盖面板，不挤压主表列宽，不改变主表行高，也不把后续回合向下推。可通过关闭按钮或 Escape 返回总览。选择回合不请求完整历史、不改变观战位置，只有进一步点击操作的“查看详情”才暂停观战跟随并定位到原始结果帧，不停止后台任务。

该视图复用轻量整局轨迹，不下载整份回放或批量加载模型正文。归档缺失时明确提示只覆盖当前执行阶段。旧服务未提供回合边界时按已有工具记录分组，并提示可能缺失无操作回合及评分。回合元数据和方案子步骤投影需要等待当前任务结束后重启服务，前端重新构建并刷新即可更新入口与界面，不需要重跑已有 run。紧凑布局本身只改前端，重新构建并刷新即可，不需要为布局重启后台任务。

方案试算和执行方案在所选回合的时间线及行动详情中，分别展示操作概要、资源净变化和按成员分组的等级与属性增量。试算使用“预览”状态标签和“预计变化”标题。摘要只展示对象、动作和结果，省去重复的口径说明。实际方案汇总逐步事件，并用本条记录保存的前后快照补充装备和技能配置。展开操作明细可按顺序阅读中文步骤，展开完整变化可查看属性前后值。原始参数与业务返回默认收起。重复提交不重复展示消耗、收益或已执行步骤，缺少记录时明确提示，不反推方案内容。该调整只涉及前端，构建后刷新页面即可查看。

## 工具结果展示

所选回合时间线与行动详情共用结构化结果面板。列表摘要只保留数量、主要资源消耗或战果统计，原始输入默认收起。

- **培养、升级和穿脱装备**：资源净变化与成员属性增量分开展示，装备槽位和技能配置保留前后对比。完整属性前后值可展开查看。
- **制作和招募**：突出成品或新成员，属性、技能和费用分别展示。只有记录中保存的返回对象进入面板。
- **队伍、怪物、库存、配方与预告查询**：时间线只保留标题与一行摘要，选中后在详情中显示紧凑表格，每页八条。表格支持筛选和分页，点击行首展开完整字段。
- **回合结算、战斗预览与日志**：先展示场数、胜负和奖励，再逐场列出结果。完整战果和战斗过程可展开查看。奖励统计只汇总战斗奖励，经验池净变化单独展示。零奖励显示为零，缺失奖励显示“未记录”。
- **备忘录**：单独展示工具返回的正文。时间线里的长正文可展开，详情保留全文。

展开、筛选或翻页只读取本次返回的数据，点击行动标题才定位时间线。预览和失败操作不展示实际局面变化。未知工具的返回字段保留可读展示。

## 整局检索与对象轨迹

单局“行动时间线”提供“所选回合”和“整局检索”两个范围，两者均保留所有工具调用，包括查询、预览、备忘录和日志中的未知工具。单回合默认逐条展示工具，只有技术性运行事件收起。侧栏的行动时间线使用相同口径。每个范围都可按工具类别、具体工具和执行状态筛选，展开“按工具汇总”可查看每种工具的次数、成功、失败、执行中和结果未明数量。具体工具选项根据实际日志生成，不依赖固定工具名单。一次调用和匹配的结果合并计一次，不按受影响对象数量重复计数。

“整局检索”顶部统计全部已记录调用，区分只读查询、只读预览、招募、解雇、天赋购买、装备制作、材料兑换、穿戴与卸下、经验分配、战术配置、付费刷新、执行方案、备忘录、结束回合和其它工具。旧版 `refresh_monsters(preview=true)` 与新版 `preview_monster_refresh` 均归为只读预览，但仍保留原工具名称用于单独筛选。查询和预览的执行成功不表示实际收益。概览不随下面的关键词或回合范围变化。

点击整局概览的类别、具体工具、状态或总次数，会清除当前筛选并查看对应调用，不改变观看位置。点击具体记录才定位到当时局面。执行结果与回合是否提交分别记录，未提交或回滚的调用也可能已执行成功，状态计数不能直接相加。“已确认成功”仅指执行成功、回合已提交且未回滚。缺少明确结果时标为结果未明，不推定成功。读取中或读取失败且没有缓存时显示未知，不显示虚假的零。仅有当前执行阶段日志时，标题和覆盖范围都会明确提示。

概览横跨整个工作区，下方仍为检索结果与所选行动详情。按工具汇总位于列表内，默认收起，展开后可滚动查看，不挤掉记录列表。手机按整页纵向查看。

整局检索可按对象名称或 ID、操作类型、状态和回合范围筛选，每页最多显示 40 条。每条结果标明所属回合、该次尝试中的操作序号、执行结果和实际变化，并提供关键输入预览。点击结果会暂停观看跟随，定位到真实历史结果帧，不暂停运行任务。原始事件和模型记录按需从对应日志读取，不能用归档字节位置去读取当前执行阶段的日志。

成功执行的方案在整局检索中保留父调用，并额外列出日志已记录的真实子操作。子操作与整局时间线共用展开逻辑，支持按类别、具体工具、名称或 ID、执行状态和回合范围检索。可读输入也参与关键词匹配，子操作不继承整批方案的对象列表，避免同批其它对象误命中。每条子操作标明方案步骤，点击后读取整个方案提交后的真实局面及父调用参数，不伪造中间帧。

总次数、执行状态计数和按工具汇总仍只统计原始调用。普通类别卡片把方案子操作并入操作总数和已确认数，悬浮说明分别列出直接调用与方案子操作的数量。未提交或已回滚的步骤计入操作总数，但不计入已确认数。“执行方案”卡片只统计父调用，悬浮说明列出包含的子操作总步数，避免与各类别重复累加。具体工具下拉框和匹配条数按检索记录计数，包含父调用与子操作，不等同于工具调用次数。失败方案、试算和未再次执行的重复提交不展开子操作。旧日志缺少子步骤时只保留父调用，不从当前局面补推。本次检索接入只改前端，后端已提供子步骤时重新构建并刷新即可。

所选回合与整局检索不再将操作摘要统一裁成两行。选中行动后，先显示具体结果摘要，输入仍常驻在靠上位置，不移到底部或整区收起。普通参数紧凑排列，字段原名与原值同行，减少重复留白。派遣等对象列表以一行一组的表格展示，技能顺序保留输入顺序，备忘保留原文。零、false、空列表和 null 不会被当成缺失参数。明确记录的空对象显示“无输入参数”，日志未记录时明确提示，不能从执行结果反推。

业务返回与实际局面变化分开展示。招募、制作、升级和配装展示已记录的成员、实际产物、实例、属性和解锁项。队伍、库存、候选、配方等查询直接展示本次返回的表格，不用当前局面替代查询结果。表格每页最多六条，可在已经返回的数据中筛选，点击名称可展开此条记录的可读字段，不额外发起工具查询。战术配置以真实返回的技能顺序和停用项为主，不在其它操作中重复铺开未改变的战术。战斗展示胜负和已记录奖励，未记录的耗时不留整列空占位。模拟和未来查询明确标注，不作为实际收益。原始 JSON 继续作为调试入口，不承担常规结果阅读。

所选回合与整局检索共用只读业务结果投影，仅从显式返回或确实记录过的前后快照提取变化对象及明确操作目标的实际状态。成功但状态未变的操作也可查看目标状态，不按请求或配方猜测产物，不重新执行游戏或评分。索引不复制整份局面、完整查询列表和完整战斗过程，只保存查询条数、简短结果与必要的标量信息。点击记录后按原游标读取所属回合的完整返回。缺少结果或变化数据时说明记录不足，不将未知视为成功或零。多路观战仍保留有界短预览，完整参数和业务返回进入单局查看。部分旧日志只在工具调用中记录参数，展示层和整局索引会按同一调用关联保留这些输入，不修改结果帧、原日志或历史定位。参数继承与业务返回投影的后端更新需要等当前任务结束后重启服务，无需改写现存日志或重跑整局。

天赋、制作配方和具体装备的详情顶部提供“本局轨迹”。天赋摘要标出已确认的解锁回合，配方摘要统计已确认制作次数和首次制作回合，装备摘要显示已记录的制作回合。展开后可查看相关制作、穿戴、换装和卸下记录。相同名称的不同装备按实例 ID 区分，回滚分支中复用 ID 的记录会保留回滚标记，不计入成功次数。

轨迹使用整局追加的 `trace.jsonl`，覆盖续跑前后，索引只保存行动字段与对象引用，不保存完整提示词或每一步的完整局面。首次读取后只索引追加内容，最多缓存四份日志索引。回合结束的记录标为已提交，尚未提交的操作和失败操作单独标注，回合重试或续跑丢弃的分支标为已回滚。续跑按实际恢复回合判断，即使此前已有回合完成事件，没有进入恢复检查点的分支也会回滚。检查点保存失败时会提示记录可能未进入恢复点。统计成功需要工具返回成功且所属回合已提交，并且没有在后续恢复时被回滚。

对象轨迹展示整局记录，可能晚于正在查看的历史快照。后续回合会有标记，只有点击定位才切换当前观看位置。没有记录不能证明没有发生，也不能推算购买或制作时间。整局原始日志缺失时，页面会明确提示只覆盖当前运行阶段，不重建局面、调用模型或补评分。首次启用轨迹接口时，需要等正在运行的任务结束，再按原参数重启 Web 服务。仅更新概览等前端内容时，重新构建并刷新页面即可。

## 曲线对比

左侧“曲线对比”是统一入口，最多比较四个 run。运行列表和历史存档多选后可点击“对比选中曲线”，实验批次也提供入口。单局和侧栏标题区的曲线按钮带入当前 run，多路观战顶部的“对比当前观战曲线”带入正在看的所有 run。CLI 存档同样可以参与曲线比较，但不能实时观战。返回原工作区会保留已保存的观战位置。

曲线页内容区独立纵向滚动，顶部栏和导航保持固定。滚轮或触摸滑动可到达下方数值表、节点详情和说明，手机底部内容避开导航栏。内容区也可获得键盘焦点，使用 Home、End 等按键滚动。滚动区固定预留滚动条占位，悬停或切换回合改变内容高度时，曲线宽度和节点位置不会随滚动条出现、消失而移动。

曲线数据更新或进度保存失败时，提示会说明当前数据可能尚未更新。相同问题合并为一处可展开摘要，展开后显示受影响的运行。接口读取错误独立显示。条件资料缺失、规则与种子不同不再触发比较提示，重复的空数据说明和数据口径长说明也不再显示。

“最近共同已记录回合”定位到当前范围内所有已选 run 均有当前三项指标数值的最近回合，不改变曲线范围，也不替代默认的跟随最新。累计收入与结算后余额分别检查各自指标，零值正常参与。曲线还未读取、范围内没有交集或某路尚无相应数值时按钮禁用，保留未知值，不用较短曲线的长度推算共同回合。控件下方显示当前回合有几路具备三项指标。

三张图共用真实回合横轴和定位回合。悬停或按图表方向键可联动数值表，差值相对图例中首个 run，数值最多保留四位小数。可调整回合范围，点击“全程 / 跟随最新”恢复完整范围和最新回合。刷新页面会恢复所选 run，资源口径与回合范围恢复默认值。

| 指标 | 默认口径 | 切换到“结算后余额” |
| --- | --- | --- |
| 经济 | 累计讨伐金币奖励 | 结算及恢复后的金币余额 |
| 经验 | 累计讨伐经验奖励 | 结算及恢复后的未分配经验池 |
| 战力 | 已记录的正式 Rank Score | 口径不变 |

关键节点放在横轴下方的独立事件轨道，不覆盖曲线。每个 run 单独一行，行号对应顶部图例，颜色与该 run 的曲线一致。经济图用“扩1”“扩2”表示成功解锁扩编 1、扩编 2，经验图用“9”表示角色首次达到或跨过 Lv9，战力图用“首”“挑”区分战胜首领与完成固定挑战。同一 run 同回合的多个节点归入同一个定位按钮，完整事件仍逐项保留。不同 run 不合并，即使发生回合和曲线数值相同。

事件按真实回合对齐。相邻节点太密时改用细刻度，不偏移发生回合或堆叠文字和数量气泡，缩小回合范围后恢复简写。悬停节点会直接在节点下方弹出详情，列出该 run 在该回合的全部事件。浮层与曲线区分离，移入浮层可继续阅读或滚动，移开后收起。键盘聚焦和手机点击也能查看，点击后可保持详情，通过关闭按钮、点击外部或 Escape 收起。节点同时联动定位虚线、小空心点与下方数值表。“所选回合关键节点”仍保留该回合各 run 的完整事件。切换累计收入或余额模式不改变节点归属。事件轨道占用独立空间，多路比较时可向下滚动查看数值表与完整详情。

图下可展开“节点详情”列表，查看当前回合范围内的全部事件。曲线数值缺失时，事件轨道仍保留该回合的节点，但不补画纵轴位置或推算评分。节点只表示该回合发生的事件，不表示它是曲线变化的唯一原因。提取仅使用已完成且未回滚的回合、成功操作、升级前后快照与实际结算战果，预览和试算不计入。首领和挑战按记录中的怪物类型识别，不从名称猜测。旧日志证据不足时不推测发生回合，也不使用可能已被后续操作改变的最终局面补节点。

累计讨伐收入不包含开局持有量，不扣招募、制作和经验分配，不代表当前余额。曲线使用成功完成回合的记录，失败及回滚尝试不作为新的结算点，试算评分不代替正式评分。缺失回合断线，未知数值不补零。缺少奖励记录时，后续累计收入保持未记录，不用已知后续奖励猜补缺口。旧续跑没有结算快照时，只允许紧邻下一回合的开局快照补充上回合余额，不使用可能已被操作改变的最终局面。

这里显示全程已记录的曲线，不随历史观战位置回退。同一存档的续跑使用权威回放中的完整历史，不把各次执行的累计值相加。曲线与差值读取已记录数据，不生成跨规则排名。

浏览器只获取轻量数值投影，不下载完整回放。服务端按文件修改时间缓存投影，运行中的选中 run 每 2.5 秒读取一次，检查点和终态变化会主动同步。回放暂不可读时可保留上次成功投影并标注过时，存档写入失败也会提示。可以手动刷新。CLI 目录不做定时轮询，进入页面或手动刷新时可更新列表。

曲线读取不调用模型、不重算评分、不重建局面，也不修改原存档。首次启用曲线及节点提取接口时，应等待当前任务结束后按原参数重启 Web 服务。仅更新事件轨道等前端展示时，重新构建并刷新页面即可。

## 停止、关页与恢复

- **关闭、刷新浏览器或网络断线**：不停止任务。
- **取消排队**：任务不会启动，也不会发出模型请求。
- **停止运行**：先请求协作退出。界面保持“停止中”，直到进程退出被确认。阻塞超过 8 秒后强制结束进程。
- **强制停止**：只能保证使用最近成功写入的检查点恢复，不能保证保存尚未完成的模型响应或当前回合。
- **关闭服务**：停止受控任务。服务异常退出后，工作进程检测到控制管道断开，也会退出，避免无限期留在后台。
- **重启服务**：历史状态保留，未确认结束的任务标记为中断，不自动重新发出模型请求。可以再次选择已保存的 API 配置手动续跑，不必重新输入密钥。

在“历史存档”中选择未完成存档并续跑，仍使用原 run 身份。续跑沿用归档中的评测参数，未完成回合可能回滚。可重新选择模型、接口和推理强度并提供凭证。

选择“从指定回合重跑”会创建独立的分支 run，已完成和中断的存档都可以作为来源。x 表示第 x 回合开局：继承前 x−1 回合的记录和备忘录，从第 x 回合重新调用模型。可选范围由连续的已完成历史与回合上限决定。来源存档的回放和原始日志保持不变，分支记录来源标识、起始回合和版本资料。分支日志保留来源证据，其中未继承的后续尝试只在分支内标为已回滚，不改变原 run。分支的当前统计只继承起点之前的记录，不累加原 run 在起点之后的用量或评分。

恢复前会检查游戏数据、运行协议、评测参数和种子。若版本不同或旧版本资料未记录，界面会列出原记录与当前值，并说明恢复可能失败或改变局面，要求点击“仍然继续”。取消不会加入队列或请求模型。确认令牌绑定本次来源存档、起始回合及当前版本，提交和工作进程启动时都会复核。排队期间来源或版本再次变化时，任务会在请求模型前失败，需重新提交并确认。

确认后按当前规则执行历史成功操作以恢复局面，并非加载完整游戏状态快照。跨版本局面可能与原记录不同，旧操作也可能已无法执行。此时会报告恢复错误，不会伪造成功或请求模型继续。跨版本执行会保留新旧版本资料并标记为 `mixed`，详情保留跨版本事实标记，标准排行榜仍排除跨版本记录。版本确认不解除 preset 边界、存档占用、必要历史完整性或冻结 `full v1` 包的完整性检查。CLI 原有严格续跑行为不变，工作台的确认仅适用于本次提交。

工作台对自己的服务目录和受控运行归档使用操作系统文件锁。同一份归档不能同时由多个工作台进程写入。CLI 和旧调试接口不参与这套锁，续跑前必须自行确认没有 CLI 或旧调试任务正在操作相同存档。

“历史存档”合并工作台的终态摘要与 `runs/llm/` 中的存档，同一 run 不重复展示。受控 run 以工作台当前状态为准，排队或执行中不同时出现在历史页。CLI 归档支持读取曲线和显式删除，存档中残留的 `running` 不证明对应进程仍存活。工作台不提供对外部 CLI 进程的停止操作。其他目录中的 CLI 运行目前不自动发现。

## 已知限制

Windows 并行验收曾观察到两个同模型任务取得相同的时间戳，生成同名存档目录，其中一个任务以 `WinError 183` 启动失败。已有目录不会被覆盖，失败记录仍可在历史中查看。当前存档目录分配逻辑尚未修复，本轮界面调整没有修改该逻辑。

## 凭证与存储

- 未保存的显式 API Key 只保留在调度器内存中，通过工作进程标准输入传递，不出现在进程命令行、工作台任务配置或浏览器本地存储中。
- 明确保存的 API 配置将密钥存入当前系统用户的凭证库，元数据保存在 `runs/.workbench/api_profiles.json`，不保存明文密钥。
- 模型服务地址不允许包含用户名、密码、查询参数或 URL 片段，请使用独立的 API Key 字段。
- 主题、筛选、关注列表、详情面板宽度和各表列宽保存在浏览器本地。移除模板功能后，不再读取或写入旧模板缓存。
- 运行、历史、API 配置、排行榜、曲线对比和工具明细表均可拖动表头右边缘调整列宽。松开后保存，取消拖动不保存；双击分隔线恢复当前列默认宽度。分隔线支持键盘左右微调、Home 和 End 定位范围端点。各列的设置值有最小宽度限制，上限为 1600 像素。表格至少铺满容器，保存的列宽总和不足时由浏览器分配剩余空间，不改写列宽偏好。超出容器时在表格内横向滚动，手机端保留表头。
- 列宽按列表和字段身份记忆，排序、筛选、数据刷新及切换 run 不会串列。容器或表头实际尺寸改变时才重新测量列宽，普通数据刷新不强制测量。拖动不触发排序、多选或行操作。列宽设置不写入存档，不改变评测规则和分数。
- 调度设置和任务摘要保存在 `runs/.workbench/`。每个任务目录包含 `state.json`、`events.jsonl` 和 `stderr.log`。运行产物继续保存为 `runs/llm/<run_id>/replay.json` 和 `trace.jsonl`。
- 模型正文、提示词和工具结果可能包含敏感数据，分享日志和归档前仍需检查。

这是可信本机工具，不提供用户认证。不要直接暴露到公网，也不要用多个 Uvicorn 服务进程共同管理同一个工作台目录。

运行图片采用职业 320 × 320px、怪物 224 × 224px：旧页面头像为 32–56px，观战立绘约 142–185px，职业装备详情需要较大的图片。`web/assets/icons/` 保存优化压缩后的 PNG，`web/workbench/src/portraits/` 保存同尺寸无损 WebP；两者由同一份原稿一次缩放生成，颜色逐像素一致。像素素材使用最近邻缩放，不增加有损压缩噪点。Pillow 只用于生成素材，应用运行和常规前端构建不依赖 Pillow。
