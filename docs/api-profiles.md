# API 配置与模型目录

打开工作台左侧“API 配置”，或访问 `/?section=apis`。配置保存在服务端，新建实验和续跑通过配置 ID 复用连接。编辑窗口会读取已保存的 API Key，直接明文显示。

## 保存和复用

1. 点击“新增 API 配置”，填写名称、接口类型、服务地址和 API Key。
2. 模型可以手动填写，也可以点击“获取模型”，再从输入框的建议列表中选择。
3. 点击“保存 API 配置”。在新建实验或续跑的每个模型行中，从“API 配置”下拉框选择已保存的连接，不必重新填写地址和密钥。

新建实验中的自定义连接也有“保存此 API 配置”按钮。仅输入密钥并启动运行不会自动持久保存密钥，只有明确保存配置才会写入系统凭证库。

点击“编辑 / 模型”后，API Key 输入框会自动填入已保存的密钥，可直接查看、修改并保存。不修改 Key 时可直接保存其它字段。清空输入框再保存会移除已保存的 Key，改用服务端环境变量，不再需要勾选清除选项。未单独保存 Key 的配置保持空白，不会将环境变量中的 Key 填入编辑框。

读取 Key 期间禁止保存。读取失败时会显示错误，不会把读取失败当成空密钥保存，仍可直接输入新的 Key 修复配置。修改服务地址、接口类型或 Key 后，先保存，再获取模型目录。保存时会提交当前编辑框中的 Key，请确认它适用于当前服务地址。

- 模型名称留空时，运行优先使用所选 API 配置的默认模型，再由适配器读取环境默认值。
- 新建实验选择配置时会填入配置的默认模型。续跑选择配置时保留原存档模型，可以手动修改。
- 一次创建多个 run 时可以使用多份 API 配置，也可混合保存的连接和临时连接。
- 任务确认加入队列时解析连接和凭证，后续编辑或删除配置不改变已排队或运行中的任务。
- 引用的配置被删除后，需要重新选择连接。服务端不会默默改用其它已保存密钥。

## 从 API 获取模型

查询由服务端发起，模型目录响应不包含密钥。模型目录查询使用 GET，不发起聊天或推理请求。不同服务的目录权限、计费和限流仍以服务方规则为准。

| 接口类型 | 基于配置地址追加的路径 | 认证方式 |
| --- | --- | --- |
| OpenAI Chat Completions / Responses | `/models` | `Authorization: Bearer ...` |
| Anthropic Messages | `/v1/models` | `x-api-key` 和 `anthropic-version` |
| Google 原生 API | `/models` | `x-goog-api-key` |

Anthropic 的配置地址与原适配器相同，通常不含末尾 `/v1`。Google 的地址应包含对应 API 版本或网关路径。OpenAI-compatible 服务通常需要包含 `/v1`，以服务方要求为准。

支持 Anthropic 和 Google 的目录分页。Google 原生目录仅保留声明支持 `generateContent` 的模型。部分 Google 网关返回 OpenAI 格式的目录，也可以识别，不会为此更换认证协议或尝试其它服务地址。

目录请求有超时、分页和响应大小限制。为防止凭证被带到其它站点，不自动跟随重定向。服务要求重定向时，应直接配置正确的最终地址。

获取失败会显示错误，仍然可以手动输入模型 ID。历史模型与已保存默认模型会明确标注来源，不会假装来自本次 API 查询。目录中出现某个模型也不证明它支持当前协议、工具调用或指定推理强度。

## 导入命令历史

在“API 配置”中点击“从命令历史导入”并确认。也可以从项目根目录执行：

```powershell
uv run python -m guild_manager_bench.api.api_history
uv run python -m guild_manager_bench.api.api_history --import
```

第一条命令只展示不含密钥的预览，第二条执行导入。默认读取已存在的 PowerShell PSReadLine、Bash 和 Zsh 历史文件，只解析本项目的 CLI 运行命令和已知批次脚本参数。

导入按协议、服务地址和凭证去重，保留历史模型，并将最近一次可解析的模型设为该配置的默认值。同一地址使用不同协议或凭证时保留为不同配置，避免把多个账号或协议混在一起。已有的连接会跳过，重复导入不新增副本。

解析器不执行历史命令。支持字面值、常见引号、续行和明确的变量引用，跳过无法解析的变量、不安全 URL 和明显有误的参数。命令曾被输入不证明请求曾成功，导入配置不能作为可用性认证。

导入不会自动访问历史服务地址，不启动历史任务，不输出原始命令或密钥，也不会修改或清理原历史文件。原命令历史中可能仍有明文密钥，请自行管理历史文件。

## 密钥与存储

- 配置元数据位于 `runs/.workbench/api_profiles.json`，包括名称、地址、默认模型、历史模型和凭证引用，不含明文密钥。
- 密钥通过 `keyring` 保存到当前系统用户的凭证库。当前 Windows 环境使用 Windows Credential Vault。
- 无可用系统凭证后端时，保存会报错，不会退回明文 JSON 文件。无桌面 Linux 环境需要先配置可用的系统凭证后端。
- 配置列表和保存响应不返回密钥，也不返回内部凭证引用或查重指纹。打开编辑窗口时，通过同源 POST `/api/workbench/api-profiles/{id}/key` 读取 Key，响应设置 `Cache-Control: no-store`。读取不向模型服务发起请求。
- 编辑窗口中的 Key 是明文，请注意屏幕共享和截图。应用不将 Key 写入浏览器本地存储、会话存储、运行配置 JSON 或进程命令行。关闭编辑窗口后不保留表单状态。
- 使用不同系统账号运行服务时，需要在该账号下重新保存凭证。仅复制元数据 JSON 不会迁移密钥。
- 保存、编辑、删除和历史导入共享文件锁。CLI 与网页同时修改时可能提示稍后重试，不会绕过锁写入。
- 未保存凭证的连接沿用适配器原有的服务端环境变量规则。请确认环境凭证适用于对应服务地址。

工作台仍是可信本机工具，不提供用户认证，不应直接暴露到公网。更新代码和安装依赖后，需要重启已有 Web 服务才能启用新的 API 路由。重启会停止受控任务，请先等待当前任务完成或确认检查点。

## 验证

```powershell
uv run pytest tests/test_api_profiles.py tests/test_api_profile_security.py -q --basetemp=runs/.pytest-api-profiles
npm run test:workbench
npm run build
uv run --with playwright python -X utf8 tests/frontend/smoke_api_profiles.py
```

浏览器验收使用本地假 API、真实工作进程和内存凭证库，不调用付费模型，也不读写用户的实际命令历史。可附加 `--lighthouse` 生成 API 配置页面的桌面报告，当前脚本使用 Windows 上 Microsoft Edge 的标准安装路径。
